Uniform-Cost Search (UCS)

Intelligent Search Algorithms · Latakia University · Cheapest first

The idea

You drive from city S to city G. Do you want the path with the fewest roads, or the path with the fewest kilometres?

BFS counts roads (steps). It finds the path with the fewest steps. But real roads have different lengths. A map app wants the shortest trip in km (or in minutes).

UCS in one sentence: always expand the cheapest node first: the node with the smallest path cost g(n).

g(n) = the real cost from the start to the node n = the sum of the road lengths on its path. Example: S → A → C has g = 10 + 5 = 15.

How does UCS remember the order?

With a priority queue. Think of a hospital: the patient who is most in need goes first, not the patient who came first. In UCS, the node with the smallest cost goes first.

  • New nodes do not go to the end. Each node goes to its place by cost.
  • UCS always takes the node at the front: the cheapest one.

    Is UCS good?
    
        
    First, three words
    
        
    
          
    WordWhat it meansOn our city map
    
          
    bbranching factor: the most children a node can haveA has 3 roads, so b = 3
    
          
    C* ("C star")the cost of the best solutionS → A → C → F → G, so C* = 18
    
          
    ε ("epsilon")the cost of the cheapest action (the shortest road)the road F–G, so ε = 1
    
        
    
        
    C*/ε = the most steps the best path can have.
          Every step costs at least ε, so a path with cost C* has at most C*/ε steps.
    
          Our map: 18 / 1 = 18 steps at most. If the shortest road was 6 km: 18 / 6 = only 3 steps.
    

        
    The four questions
    
        
    
          
    QuestionAnswerWhy
    
          
    Complete?
    Does it find a solution if one exists?    		
            YesIf every action costs at least ε > 0. Each step makes the cost bigger,
              so UCS can not walk on one path forever.
    
          
    Optimal?
    Is the solution the cheapest?    		
            YesIf every cost > 0. UCS takes the nodes from the cheapest up,
              so the first goal it takes is the cheapest one.
    
          
    TimeO(b1 + C*/ε)UCS may look at every path that is cheaper than C*.
              These paths have at most C*/ε steps.
    
          
    SpaceO(b1 + C*/ε)The same: like BFS, the frontier can be very big.
    
        
    
        
    C*/ε is rounded down to a whole number.
    
        
    Example: b = 3, C*/ε = 18, so in the worst case 319 ≈ 1 billion nodes.
          This is only the worst case: on our map UCS expanded 6 nodes, because most roads are long.
          With small ε (many cheap steps) the number grows very fast.
    
        
    All actions cost the same? Then C*/ε = d (the depth of the goal), and UCS works like BFS: O(bd+1).
    
          Example: the maze, every step costs 1, the goal is 10 steps away: C* = 10, ε = 1, so C*/ε = 10 = d.

    The weak point: UCS does not know where the goal is. It only looks back (the cost so far, g),

    UCS is the only one of the four that finds the cheapest path when the costs are different.
    
          
    Fun fact: UCS is almost the same as Dijkstra's algorithm (1959).
            Dijkstra finds the cheapest path to every city; UCS stops at the goal.
