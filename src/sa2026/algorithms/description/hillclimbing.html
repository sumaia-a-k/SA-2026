Hill Climbing

Intelligent Search Algorithms · Latakia University · Local search: after Greedy, A* and Beam Search

The idea

You are on a mountain in thick fog, and you want to reach the lowest point. You can only see the ground around your feet. So at every step you go to the lowest place next to you. When no place around you is lower, you stop.

Hill Climbing in one sentence: keep only one state. Look at all its neighbours and move to the best one (the smallest h), but only if it is better than where you are now. If no neighbour is better, stop.

h is a cost or a distance: smaller is better		 the smallest hh(best) < h(current)
the maximum (maximization)
h is a score: bigger is better		 the biggest hh(best) > h(current)

On this page we minimize: our h is a distance to the goal, so smaller is better and we go down to h = 0. The name "climbing" comes from maximization (climb up to the top). It is the same algorithm, upside down.

No frontier, no explored set, no going back. Only the current state.

The price: it can stop at a place that is not the goal. We say it is stuck.

Two neighbours with the same smallest h: in this course we take the first one (on the city map: ABC order). Some books choose one at random.

History

    The 8-queens problem

    Put 8 queens on a chess board so that no two attack each other. A queen attacks along its row, its column and its two diagonals.

    • State: one queen in each row and in each column, always. This part is easy, so we start with it: no two queens share a row or a column, and only the diagonals can be a problem.
    • Neighbour: swap two queens: the queen of column i takes the row of the queen of column j, and the other way. So it is still one queen in each row and column. 8 × 7 / 2 = 28 neighbours.
    • h: the number of pairs of queens on the same diagonal. We count a pair even if another queen stands between them.
    • Goal: h = 0. There are 8! = 40,320 such boards, and 92 of them are solutions.

    Russell & Norvig use another version: one queen in each column, and a move takes one queen up or down in its column (56 neighbours). Then two queens can share a row, and one climb solves only about 14% of the boards. Here we do not need a path: only the final board is the answer.

    2. A way out: random restart
    
          
    When it is stuck, start again from a new random state. Repeat until you find the goal.
    
          
    function RandomRestart(problem, maxClimbs):    repeat maxClimbs times:        # any state must be allowed as a start        start ← a random state        result ← HillClimbing(problem, start)        if result is not stuck: return result   # the goal    return failure        # no goal after maxClimbs climbs
    
          
    HillClimbing(problem, start) is the code of step 3, but it starts from start.
            maxClimbs is a limit, so the search always stops.
    
        
    
        
    
          
    3. Another kind: Stochastic Hill Climbing
    
          
    Our Hill Climbing (steepest) takes the best neighbour.
            Stochastic Hill Climbing takes a random one of the better neighbours.
    
          
    function StochasticHillClimbing(problem):    current ← the start state    loop:        if isGoal(current): return current    # success        better ← the neighbours with h < h(current)        if better is empty: return stuck        current ← a random state from better
    
          
    The green lines are different from step 3. It is not a way out: it stops for the same reason
            (no neighbour is better), in the same 3 kinds of places.
            It usually needs more moves. Because it is random, two runs from the same start can end in different places.
    
          
    Here every better neighbour has the same chance. Some books give a bigger chance to a much
            better neighbour (Russell & Norvig).
    
        
    
    
    
  
    

  
  
    
    
    
      
    
        
    Is Hill Climbing good?
    
        
    b = the number of neighbours of a state.
    
        
    
          
    QuestionAnswerWhy
    
          
    Complete?
    Does it find a solution if one exists?    		
            NoIt can get stuck: local minimum, plateau, ridge.
              The city map with the misleading guess: stuck at C.
    
          
    Optimal?
    Is the solution the cheapest?    		
            NoIt uses only h. With the GPS guess it pays 21 km, but 18 km is possible.
    
          
    TimeUsually smallEach move looks at all b neighbours. It always stops, because h gets smaller
              at every move. With whole-number h: at most h(start) moves (8-queens: h ≤ 28).

          the chance goes up to 100% (Russell & Norvig). But we can not say how many climbs it needs.

    Hill Climbing in short
    
          
    Good: very simple, very little memory, often fast. Good for big problems where only the
            final state matters (8-queens).
    
          
    Bad: not complete, not optimal. It gets stuck in a local minimum, on a plateau or on a ridge.
    
          
    A way out: random restart (step 4).
