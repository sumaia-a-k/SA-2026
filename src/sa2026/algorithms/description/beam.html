Beam Search

Intelligent Search Algorithms · Latakia University · Informed search: after Greedy and A*

The idea

A small waiting room has only k chairs. A new person comes, but the room is full. So the person with the worst number must leave, and never comes back.

Beam Search in one sentence: it is Greedy, but the frontier can keep only k nodes. After each expansion, we look at the whole frontier (old nodes and new children together), keep the k nodes with the smallest h, and throw away the rest.
f(n) = h(n)  ·  at most k nodes in the frontier

k is called the beam width. We choose it before the search starts.

Why?

Greedy keeps every node it makes. On a big problem (the 8-puzzle, a real map) the frontier becomes huge and fills the memory. Beam Search keeps the frontier small.

The price: a node that we throw away is gone. If the way to the goal was there, we lose it.

Where is it used? When there are too many ways to keep them all. For example, machine translation and speech recognition: the program keeps only the k best sentences so far, not all of them.

Not sure about h or Greedy? Read heuristics.html and greedy.html.

    Is Beam Search good?
    
        
    k = the beam width. b = the branching factor (the most children a node can have).
    
        
    
          
    QuestionAnswerWhy
    
          
    Complete?
    Does it find a solution if one exists?    		
            No
            A node that we throw away never comes back. If the way to the goal was in it, we lose it.
              Tree search can also go around a loop, like Greedy.
    
          
    Optimal?
    Is the solution the cheapest?    		
            NoIt uses only h, like Greedy. It can also throw away the cheapest way.
    
          
    TimeDepends on hEach step takes 1 node, makes at most b children and keeps k.
              The frontier is small, so each step is cheap. The number of steps depends on the guess.
    
          
    SpaceSmallAfter each step the frontier has at most k nodes
              (k + b for a moment, while we add the children). Graph search also keeps the explored set.
    
        
    
        
    Good point: with the GPS guess, Beam Search with k = 1 finds the same path as Greedy
          (). After each step, its frontier has at most 1 node. Greedy's frontier grows to  nodes.
    

        
    k changes everything
    
        
    
          
    
            
    kWhat happens
    
            
    1Only one node in the frontier. It always goes to the best child of the current node,
              and never goes back. (Very close to Hill Climbing, the next lesson.)
    
            
    smallLittle memory, fast. It can throw away the way to the goal.
    
            
    biggerMore memory and more work in each step. It keeps more nodes, so it throws away less.
    
            
    no limitNothing is thrown away. It is Greedy.
    
          
    
        
    
      
    

      
    
        
    
          
    How Beam Search fails
    
          
    Misleading guess, graph search, k = 1. Only one place in the frontier:
    
          
      
            
    1. S: children A2, B6. Keep A. Throw away B.
      2. 
            
    2. A: children C1, D7, S9. Keep C. Throw away D and S.
      3. 
            
    3. C: children A2, F6. A has the smaller h, so keep A. Throw away F.
      4. 
            
    4. Take A: it is already explored. Skip it. The frontier is empty.
      5. 
          
    
          
    Failure! But a path exists: S → B → E → G (21 km).
            We threw away B, D and F: every way to G.
    
          
    With k = 2 the same map works: B stays in the frontier, and Beam Search finds S → B → E → G.
    
        
    
        
    
          
    Beam Search in short
    
          
    Good: small memory, the frontier keeps at most k nodes. Simple: Greedy + one line.
    
          
    Bad: not complete, not optimal. A bad guess or a small k can throw away the goal.
    
          
    Next lesson: Hill Climbing. It keeps only one state, like k = 1.
