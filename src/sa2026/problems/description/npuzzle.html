The N-Puzzle Problem

Describing a problem: states, actions, goal and cost

The question

A board has n × n cells: n² − 1 tiles with numbers, and one empty cell. With n = 3 this is the 8-puzzle, with n = 4 the 15-puzzle.

  • In one step, slide one tile that is next to the empty cell into the empty cell (up, down, left or right).
  • The goal: the numbers in order, 1, 2, 3, ... and the empty cell at the end (bottom right).
  • Every move costs 1.

Why do we move the empty cell, and not the tiles? It is the same move, seen from the other side: "move the empty cell up" = "the tile above slides down". But it is much simpler: there are only 4 actions (not 8 tiles × 4 directions = 32), and at most 4 of them can work.

From index to (row, col)

The board has 2 dimensions, but the list has only 1. We go row by row:

  • index = row × n + col
  • row = index / n (integer division) and col = index % n

How does an action make the next state?

  1. Find the empty cell: the index of 0, then its row and col.
  2. Check the border: "up" needs row > 0, "down" needs row < n − 1, "left" needs col > 0, "right" needs col < n − 1. If not, return an empty list.
  3. Make a copy of the state.
  4. In the copy, swap the 0 with the tile next to it.
  5. Return a list with the new state.
Why a copy? The old state is still inside a node of the search tree (and maybe in the explored set). If we change it, the path back to the start is broken, and its hashCode() changes inside the set. Never change a state after it is made.

How big is it?

Branching factor b: the empty cell in a corner has 2 moves, on a side 3 moves, in the middle 4 moves.

For our algorithms: BFS can solve the 8-puzzle (181,440 states fit in memory), but the 15-puzzle has about 10 trillion states. That is too much for BFS. For it we will need a heuristic and A*. A simple one: the number of tiles in the wrong place (Hamming distance).

Can every board be solved? No!

Only half of all orders of the tiles can reach the goal. If we make a random board with Collections.shuffle(tiles), half of the time the puzzle has no solution, and the search explores every reachable state before it can say "failure". Try "Random tiles" above.

Examples

Step 1 · Count the inversions

An inversion is a pair of tiles in the wrong order: a bigger number that comes before a smaller one.

  1. Read the board row by row, like a sentence. Skip the empty cell.
  2. For each tile, count the smaller tiles that come after it.
  3. Add up all the counts.

Step 2 · Use the rule for the board size

n odd (3 × 3): the board can be solved if the number of inversions is even.
n even (4 × 4): count the row of the empty cell from the bottom (the bottom row is 1, then 2, 3, 4). The board can be solved if inversions + that row is odd.

Step 3 · Why does the rule work? Move and watch

Some numbers never change between even and odd, whatever move you make. The goal has these numbers: 3 × 3: 0 inversions, even. 4 × 4: 0 inversions + row 1 = 1, odd. So a board with the other one (odd for 3 × 3, even for 4 × 4) can never reach the goal.

Move the empty cell
Move left or right: the tile slides in the same row, so it keeps its place in the reading order. The inversions do not change. The row of the empty cell does not change.
Move up or down: in the reading order the tile jumps over the n − 1 tiles between its old and new place. Each tile it jumps over adds 1 inversion or removes 1.
  • 3 × 3: it jumps over 2 tiles, so the change is −2, 0 or +2: always even. Even/odd stays.
  • 4 × 4: it jumps over 3 tiles, so the change is −3, −1, +1 or +3: always odd. Even/odd flips! But the row of the empty cell changes by 1, so it flips too. Two flips: the sum keeps its even/odd.
A better way to make a random start: start from the goal and do many random moves (like the "Shuffle" button). Every move can be undone, so the board can always be solved. In our code: the constructor of NpuzzleProblem checks every start board with isSolvable(). A board with no solution gives a clear error before the search starts. For tests we use three boards that can be solved: easy(), medium() and hard().

1. From the goal state, how many next states are there?

Only 2. The empty cell is in a corner: only "up" and "left" work. The other 2 actions give an empty list.

2. Is the size n part of the state?

4. Can [1, 2, 3, 4, 5, 6, 8, 7, 0] be solved? (only 7 and 8 are swapped)

No. It has 1 inversion (8 before 7), an odd number. You can not swap two tiles with legal moves.

5. What goes wrong if apply() swaps the tiles in the old state, not in a copy?

The parent node now has the new board too. The path from the start is wrong, and a state in the explored set changes its hashCode, so the set can not find it any more.

6. What must equals() and hashCode() of the state use?

The list of tiles. Two states are the same if their lists are the same. Without them, graph search can not find repeated states.

7. The empty cell moves up and then down. What happens to the state?

We are back at the same state. This is a cycle of 2 steps, so DFS tree search can go up, down, up, down ... forever. Use graph search or the cycle check.
