# SA-2026 – C++ version

> **Note:** this C++ code was generated by AI, based on the Java code in [`../src`](../src).
> If you find a place where it does not match the Java code, please tell your teacher.

This folder has the same code as the Java version: the same classes, the same method names, the same algorithms and the same examples.
It also prints the same output.
One small difference: the unfinished student maze demo crashes in Java (it gets `null` from `getActions()`), but in C++ it gets an empty list, so it does not crash.

You can work in Java, Python or C++. Choose the language you are more comfortable with.

## What you need

A **C++ compiler that knows C++17**: **g++ (GCC) 9 or newer**.

| Your system | How to get g++ |
|---|---|
| Windows | Install MinGW-w64 GCC. The easy way: run `winget install BrechtSanders.WinLibs.POSIX.UCRT` and then open a **new** terminal. (MSYS2 also works.) |
| macOS | Run `xcode-select --install`. On a Mac, `g++` is really the clang compiler. It works too. |
| Linux | Run `sudo apt install g++` (Ubuntu, Debian) or use the package manager of your system. |

Check that it works:

```
g++ --version
```

## How to run

Open a terminal **inside the `SA-2026/cpp` folder** (the folder with this README in it).

Like in Java, there are two scripts that do the same job: `run.bat` and `run.sh`.
**Choose the script by your terminal, not by your computer:**

| Your terminal | Command |
|---|---|
| Windows **Command Prompt** (cmd) | `run.bat` |
| Windows **PowerShell** (also the default VS Code terminal on Windows) | `.\run.bat` |
| **Git Bash**, **Linux** or **macOS** | `./run.sh` |

In Java you compile once, and then you can run any class.
In C++ every program has its **own `main()` function**, and you can't put two `main()` functions in one program.
So the script builds and runs **one program each time**. You give the program name. It is the same as the Java class name:

| What | Java (inside `SA-2026`) | C++ (inside `SA-2026/cpp`) |
|---|---|---|
| Run the main program | `.\run.bat` | `.\run.bat` |
| Maze demo | `java -cp out sa2026.problems.maze.MazeDemo` | `.\run.bat sa2026.problems.maze.MazeDemo` |
| Word ladder demo | `java -cp out sa2026.problems.wordladder.WordLadderDemo` | `.\run.bat sa2026.problems.wordladder.WordLadderDemo` |
| Maze demo (student version) | `java -cp out sa2026.problems.incomplete_code.maze.MazeDemo` | `.\run.bat sa2026.problems.incomplete_code.maze.MazeDemo` |
| Word ladder demo (student version) | `java -cp out sa2026.problems.incomplete_code.wordladder.WordLadderDemo` | `.\run.bat sa2026.problems.incomplete_code.wordladder.WordLadderDemo` |
| Check your BFS (student version) | `java -cp out sa2026.algorithms.incomplete_code.BFSDemo` | `.\run.bat sa2026.algorithms.incomplete_code.BFSDemo` |
| Check your DFS (student version) | `java -cp out sa2026.algorithms.incomplete_code.DFSDemo` | `.\run.bat sa2026.algorithms.incomplete_code.DFSDemo` |

In Git Bash, Linux or macOS, write `./run.sh` instead of `.\run.bat`.

The script does these steps:

1. It finds the file of the program, for example `src/sa2026/problems/maze/MazeDemo.cpp`.
2. It writes the file `out/all.cpp`. It has one `#include` line for every other `.cpp` file in `src` (it skips the files that have a `main()`), and one for the program file.
3. It compiles `out/all.cpp` with `g++` into one program in the `out` folder, for example `out/sa2026.problems.maze.MazeDemo.exe`.
4. It runs the program.

Why one `all.cpp` file? Every `.cpp` file includes the same big library headers (like `<iostream>`).
If we compile 20 files one by one, the compiler reads these headers 20 times, and it takes about 20 seconds.
With one file, it reads them once, and it takes about 3 seconds.
The error messages still show the real file and line, for example `src/sa2026/core/Node.cpp:12`.

The script compiles again every time, so you always run the newest code.
If the code has an error, it stops at step 3 and prints `Build failed`.
Before that, it checks the files one by one, so the error is shown in the right file.
(If a file is broken at its very end, for example a missing `}`, the compiler can show the error in the *next* file of `all.cpp`.)
So a failed build takes a few seconds more.

On Git Bash, macOS or Linux, if you get `Permission denied`, use `bash run.sh`, or run `chmod +x run.sh` once.

### Rule for files with `main()`

The script knows that a file has a `main()` from its name: it is called `Main.cpp`, or its name ends with `Demo.cpp`.
If you write a new program with a `main()`, give it a name like `MyTestDemo.cpp`.

### Common errors

| Error | What it means |
|---|---|
| `g++ not found` or `'g++' is not recognized` | g++ is not installed, or the terminal was open before you installed it. Open a new terminal. |
| `undefined reference to ...` | You **declared** a method in the `.h` file, but you didn't **write** it in the `.cpp` file (or the name is different). You will see this often in the student TODOs. |
| `redefinition of 'int main()'` | Two files with a `main()` are in the build. See the rule above. |
| `... not found. Check the program name.` | The program name is wrong. Write it like the Java class name, for example `sa2026.problems.maze.MazeDemo`. |

### VS Code

The "Run C/C++ File" button compiles **only the open file**, so you get `undefined reference` errors. Use the terminal command.

## Folder structure

The folders are the same as in Java. Each Java class becomes **two files**:

- the `.h` file (header) says what the class **has**: its fields and the names of its methods;
- the `.cpp` file has the **code** of the methods.

The interfaces (`State`, `IAction`, `HeuristicFunction`) have only a `.h` file, because they have no code.

## From Java to C++

The class and method names are the **same as in Java** and in the UML (`getInitialState()`, `isGoal()`, `equals()`, `hashCode()`, `toString()`).
C++ has no single naming style, so we kept the Java names.

| Java | C++ | Note |
|---|---|---|
| `MazeState.java` | `MazeState.h` + `MazeState.cpp` | see "Folder structure" |
| `package sa2026.core;` | `namespace sa2026::core { ... }` | |
| `import sa2026.core.State;` | `#include "sa2026/core/State.h"` | `using sa2026::core::State;` lets you write `State` instead of the long name |
| `interface State` | a class with only pure virtual methods (`= 0`) | |
| `abstract class Problem` | a class with at least one pure virtual method | |
| `class MazeState implements State` | `class MazeState : public core::State` | |
| `@Override` | `override` | |
| `final` field | `const` field | |
| `static` field | `inline static` field | |
| `State s` (a reference) | `StatePtr s` | `StatePtr` = `std::shared_ptr<const State>`, see below |
| `null` | `nullptr` | |
| `new MazeState(1, 2)` | `std::make_shared<MazeState>(1, 2)` | |
| `node.getState()` | `node->getState()` | use `->` with a pointer, `.` with an object |
| `List<State>`, `ArrayList` | `std::vector<StatePtr>` | |
| `HashSet<String>` | `std::unordered_set<std::string>` | |
| `HashSet<State>` | `core::StateSet` | a hash set of states, see `core/State.h` |
| `Queue<Node>` / `LinkedList` | `std::queue<NodePtr>` | `push()` adds at the end, `front()` reads the first, `pop()` removes it |
| `Deque<Node>` / `ArrayDeque` used as a stack | `std::stack<NodePtr>` | `push()` puts on the top, `top()` reads the top, `pop()` removes it |
| `System.out.printf(...)` | `std::printf(...)` | the same `%d`, `%s` codes |
| `(MazeState) s` | `dynamic_cast<const MazeState&>(*s)` | |
| `o instanceof MazeState` | `dynamic_cast<const MazeState*>(&o) != nullptr` | |
| `String...` | `std::vector<std::string>` | call it with braces: `Maze::fromLines({"S.#", "..G"})` |
| `System.out.println(x)` | `std::cout << x << std::endl;` | |
| `IllegalArgumentException` | `std::invalid_argument` | |
| `UnsupportedOperationException` | `std::logic_error` | |
| `this(...)`, `super(...)` | `: Node(...)`, `: SearchAlgorithm(...)` | written after the constructor, in the initializer list |

## C++ things that are more than beginner level

If you only know basic C++ (variables, `if`, loops, functions, `cout`), these parts of the code may be new to you.
Most of them also have a short comment in the code.

| Topic | Where you see it | In short |
|---|---|---|
| `.h` and `.cpp` files, `#include`, `#pragma once` | every class | The `.h` says what a class has, the `.cpp` has the code. `#include` copies a `.h` file in. `#pragma once` = include this file only once. |
| Namespaces, `::`, `using` | every file | A namespace is like a Java package. `sa2026::core::State` is the full name. |
| `public:`, `private:`, `protected:` | every class | Like in Java, but written once for a group of members. |
| `const` methods | `bool isGoal() const` | The method promises not to change the object. |
| References: `const std::string& name` | most methods | `&` = use the original value, don't make a copy. `const` = we only read it. |
| Pointers: `*`, `->`, `nullptr` | `Node.cpp`, the demos | A pointer holds the address of an object. `p->x` uses the object it points to. `*p` is the object itself. |
| Smart pointers: `std::shared_ptr`, `std::make_shared` | `StatePtr`, `ActionPtr`, `NodePtr`, `MazePtr` | Like a Java reference: the object is deleted automatically when nobody uses it. You never write `delete`. |
| `virtual`, `= 0`, `override` | `core/State.h`, `core/Problem.h` | `virtual` = a child class can replace the method. `= 0` = the child **must** write it. |
| Virtual destructor: `virtual ~State() = default;` | the interfaces | Needed in a parent class, so the child object is deleted correctly. |
| Initializer list: `: row(row), col(col) {}` | the constructors | Gives the fields their first value. `const` fields can get a value only here. |
| One constructor calls another | `core/Node.cpp` | `Node(state) : Node(state, nullptr, nullptr, 0.0) {}` is like `this(...)` in Java. |
| `inline static` fields | `MazeState.h`, `WordLadderState.h` | One value shared by all objects. `inline` lets us write it in the `.h` file. |
| `dynamic_cast` | `MazeAction.cpp`, `MazeState.cpp` | Changes a `State` into a `MazeState`. With `&` it throws an error if the type is wrong. With `*` it gives `nullptr`. |
| Forward declaration: `class SearchAlgorithm;` | `core/Problem.h`, `core/Node.h` | "This class exists." It lets two classes use each other without a circular include. |
| `operator<<` | `core/State.h`, `core/Node.h` | Lets us write `std::cout << state`. |
| `std::vector`, `std::unordered_set` | everywhere | A list that can grow (like `ArrayList`) and a hash set (like `HashSet`). |
| `return {};` and `return {next};` | `MazeAction.cpp` | An empty vector, and a vector with one item. |
| Range `for` loop | `for (const ActionPtr& action : problem.getActions())` | Like `for (IAction action : ...)` in Java. |
| `throw std::invalid_argument(...)` | `Maze.cpp`, `WordLadderProblem.cpp` | Throws an error, like `throw new IllegalArgumentException(...)` in Java. |
| `std::queue` | `algorithms/BFS.cpp` | A FIFO queue. Taking a node out needs two steps: `front()` reads it, `pop()` removes it. |
| `std::stack` | `algorithms/DFS.cpp` | A LIFO stack. Taking a node out needs two steps: `top()` reads it, `pop()` removes it. |
| `StateHash`, `StateEqual`, `operator()` | `core/State.h` | A hash set must know how to hash and compare our states. These two small structs call `hashCode()` and `equals()`. `operator()` lets us use an object like a function. |
| `namespace finished = sa2026::algorithms;` | `algorithms/incomplete_code/BFSDemo.cpp` | A short name for a long namespace. |
| `std::boolalpha`, `std::flush` | the demos | `boolalpha` prints `true` / `false` instead of `1` / `0`. `flush` shows the text now, not later. |
| A `static` function outside a class | the demos | The function can be used only in this file (like `private` in Java). |
| `static_cast<int>(lines.size())` | `Maze.cpp` | `size()` gives an unsigned number. We change it to `int` to compare it with `int` values. |
| `std::move`, `std::ostringstream` | `core/Node.cpp` | `std::move` saves a copy. `ostringstream` builds a string with `<<`. You can skip these for now. |
